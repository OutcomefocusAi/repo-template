What this change does: It moves the template to OpenSpec 2.1.1 and Ponytail ebd8654. Because 2.1.1 stops
writing a version stamp into its skills and installs skills into the home folder unless told not to,
the pin check now accepts skills with no stamp (but still rejects stale or mixed stamps), and the
skills check asks OpenSpec to write the skills into a scratch repository with a scratch home folder.
It also makes CI install OpenSpec's dependencies only from versions published before a fixed time,
and rejects the ways QA found to get around that.

Findings found during review and already fixed on this branch (test first):
1. **Install moved into another step's literal block passed** (scripts/check-openspec-pin.sh, run_block)
   - What this is: The check must make sure the install line runs as one shell command inside a run: | block.
   - Problem: It looked for the nearest run: line above, so an install placed under
     "with: script: |" of a later step, after an earlier run: | step, passed. Found by the mutation pass (m07 survived).
   - Fix: Find the block's real parent, the nearest line above with less indentation, and require it to be run: |.
     Failing test first in a4064d1, fix in 4da297c.
   - If we skip it: An install that npm never sees as the CI install line could carry other options.
2. **Temporary HOME existence was untested** (scripts/check-openspec-skills.sh, mkdir "$tmp/home")
   - What this is: The skills check gives OpenSpec a scratch home folder.
   - Problem: Deleting the mkdir passed every test (m22 survived), though npx and OpenSpec expect HOME to exist.
   - Fix: The stub now records whether HOME exists and the test fails when it does not (a4064d1).
   - If we skip it: A later edit could drop the folder and break the check with a real CLI only.

Open findings: none in Must fix or Should fix.
